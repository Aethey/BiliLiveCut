# 第一次完成工作流

先按[安装方式](getting-started.md)准备环境。下面以 Web 工作台操作为主；CLI 对应命令见[录制指南](../features/recording.md)。

## 登录并检查环境

启动服务后访问终端输出的地址。设置 `ADMIN_PASSWORD` 的源码/Portable 使用管理员账号 `admin` 和部署密码；未设置部署密码的 Docker 先按容器日志中的初始化码设密。

管理员登录与 Bilibili 登录相互独立。要使用平台登录态，在账号登录页面申请二维码，用手机 Bilibili 扫描并确认。服务器无需图形桌面；异常恢复见[账号与登录](login.md)。

## 准备输入

选择一种方式：

- **直播**：添加已获授权的直播间，开始一段短录制。需要自动守候时，再开启房间的自动录制和分析。
- **已有视频**：打开“录播分析”，上传短视频，可选导入配套弹幕，提交后检查预处理和分段分析状态。

录制与导入的条件、文件格式和故障处理分别见[直播录制](../features/recording.md)与[录播导入](../features/recording-import.md)。

## 转写与分析

在设置中心选择 ASR 引擎、模型和设备。CPU 转写需安装所选引擎及模型；CUDA 还需要匹配的运行时与设备支持。首次模型下载可能耗时。

查看场次转写与热点时间线。预处理完成不等于分析完成；模型缺失、转写失败和语音证据不足需要分别处理。未配置 LLM 服务商时不调用 LLM；远程 ASR 是独立选项，仍可能上传音频。具体回退见[转写与模型](../features/asr.md)。

## 审核与出片

检查候选的标题、时间边界、字幕与预览，确认后再渲染。后台作业可在任务队列查看，退出浏览器不会主动停止服务端录制或渲染。生成成品后确认视频可播放、字幕时序正确，再按需要准备上传。

上传默认使用手动材料导出；真实投稿需要显式配置上传工具与开关。未知上传结果先核对平台，避免重复投稿。详见[审核与剪辑](../features/review-render.md)和[上传与发布](../features/publishing.md)。

## 保存验收结果

记录程序版本、输入场次和实际执行的引擎。先验证短输入的完整流程，再扩大录制时长与并发。问题定位入口见[故障排查](../features/troubleshooting.md)。
