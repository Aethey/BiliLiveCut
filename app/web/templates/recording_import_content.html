导入录播文件

可多选按小时分段的录播，按文件名自然排序逐个上传。支持 MP4、MKV、FLV、TS、MOV、WebM、M4V，每个最大 50 GiB，需要有音轨。

可多选 XML、JSON、SRT、ASS，每个最大 32 MiB。批量按主文件名配对，例如 01.mp4 对应 01.xml 或 01.mp4.xml；单视频仍可手动选择不同名弹幕。缺少弹幕可直接分析，重名或多余弹幕会提示修正。

每段弹幕使用对应视频内的相对时间；此偏移应用到本批每段视频。通常填 0；正数把弹幕向视频后方移动。SRT、ASS 按每条开始时间读取文本。

从文件到精彩片段

  1. 准备素材

    文件复制到运行 BiliLiveCut 的机器，保留你的原文件。

  2. 预处理

    检查媒体、按关键帧分段，统一弹幕时间轴。长视频可能需要数分钟。

  3. 转写与分析

    所选 ASR 引擎完成语音转写，再按现有 LLM 配置整理文本、分析热点和总结整场，结果进入场次时间线。

所有文件上传并提交后可关闭页面，后台会继续处理。上传期间关闭页面会丢失尚未创建的队列；已创建记录可在下方继续。不会自动投稿；候选片段由你审核。

格式与存储说明

JSON 示例：

{"comments":[{"offset_s":1.25,"text":"高能！"}]}

XML 使用 B 站 d 节点的 p 属性秒数。字幕只作为文本事件，语音仍由所选 ASR 引擎转写。

预处理需要额外一份视频大小加 256 MiB 的空间。成功后会删除上传副本，保留分析分段；未完成导入可以清理。时间线以导入时刻为原点，不代表原始开播日期。

LLM 沿用设置中心的服务商、开关和预算；选择远程 ASR 会上传标准化音频至所配转写服务，转写文本及相关分析上下文可发送给所配置的 LLM。未配置服务商时沿用现有规则回退，整场 LLM 总结会提示生成失败，可在配置后重试。
